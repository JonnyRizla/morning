## Addy Osmani
- **Human judgment doesn't leave the software factory. It relocates.** (blog, 2026-08-21) [link](https://addyosmani.com/blog/human-judgment-doesnt-leave-the-software/)
  He defines a "software factory" as a repeatable loop around software work, and argues
  the mistake is assuming automation removes human judgment rather than moving it
  upstream — to product intent, system design and setting the quality bar. He coins
  several terms worth having: a "lights-on factory" that keeps deliberate human
  oversight at chosen points, a "verification budget" spread across the lifecycle the
  way a performance budget is, and "comprehension debt" for the gap between how fast
  code is generated and how fast humans can understand it.

  His sharpest line is that the number of checks is not quality — you have to tune for
  signal-to-noise and be willing to relax constraints as deliberately as you tighten
  them. Runs get classified success, flawed, blocked or manual, and a human still owns
  what ships.

## Daniel Chalef
- **Defending Agent Memory Against Poisoning** (blog, 2026-09-02) [link](https://blog.getzep.com/defending-agent-memory-poisoning/)
  The framing is the useful bit: memory poisoning is prompt injection with persistence.
  One poisoned message, page or document can shape every later session, because
  durable memory turns a single injection into a standing instruction. The stated
  principle is that the model is not the security boundary — application code has to
  control every write, every read and every external action.

  The defences listed are controlled writes, external provenance tracking, scoped
  retrieval filtering, instruction isolation and deterministic action authorization.
  Zep's own angle is that its graph carries provenance in episode metadata and stores
  bi-temporal facts, so history survives even when a later claim contradicts an earlier
  one and you can trace where a belief entered. Directly relevant to anything keeping
  long-lived agent memory.

## Robin Hanson
- **Modern Worries** (blog, 2026-09-01) [link](https://www.overcomingbias.com/p/modern-worries)
  The claim is structural: "Hope is more fragile than fear. Good outcomes often require
  that many things all go well, while bad outcomes often need only one particular thing
  to go wrong." Over a single day, your hopes and fears are about equally sized. Widen
  the frame to global prospects over fifty years and fear dominates, purely because of
  that asymmetry in how many things have to hold.

  The second move is that knowledge growth makes this worse rather than better. Every
  newly understood technology, institution or cognitive bias is fresh raw material for
  constructing a plausible disaster scenario, so a society that understands more of its
  own interconnections necessarily has more to worry about. He points at AI as the live
  case: concrete harms are still rare, but the supply of imaginable ones is enormous.

## Topic: Knowledge graphs, GraphRAG, temporal graphs
- **Graphiti MCP server v1.1.0** (github, 2026-09-01) [link](https://github.com/getzep/graphiti/releases/tag/mcp-v1.1.0)
  A configuration bug with real blast radius. The MCP server ignored the Neo4j database
  setting inconsistently: `add_memory` and `search` could hit the server's home database
  while every other operation used the configured one, so writes and reads could land in
  different places without erroring. All operations now use the configured database, and
  `NEO4J_DATABASE` should be set explicitly in the environment or `config.yaml`.

  The same fix went into the core library alongside it, where `Neo4jDriver.execute_query()`
  had been bypassing the driver's database setting while session-based writes respected
  it. That one is a flagged behaviour change for self-hosted Neo4j Enterprise
  deployments with custom database configuration; standard setups on the default `neo4j`
  database need no action.
