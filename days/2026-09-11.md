- **Managed Agents get a third permission policy: the server decides each call** (github, 2026-09-10) [link](https://github.com/anthropics/skills/commit/34040c9c568585f6929bedeaad110ad08f079624)
  `auto` joins `always_allow` and `always_ask`, and neither toolset kind defaults to it. Under `auto` the server evaluates each call against the tool, its input and the session's content so far, with exactly three outcomes: it runs without reaching your client; it is denied as high-risk, the agent receives `Permission to use {tool_name} has been denied.` as an error tool result, the session keeps running, and the client cannot override it; or the server reaches no determination and pauses as `always_ask` does. Every `agent.tool_use` event now carries `evaluated_permission` and an `evaluation` object naming the policy and a `reason_code`; client guides now gate on `evaluated_permission === 'ask'`, not the configured policy.

  The injection boundary is stated plainly: text in a `user.message` counts as *your* intent and can get a call allowed, while the same words in a tool result, a fetched page or an MCP response carry no weight. So relaying untrusted end-user text through `user.message` can allow a call — the advice is `always_ask` on anything you would not let that user run. A boxed warning adds that `auto` is not a human checkpoint.
