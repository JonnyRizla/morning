- **Kitty graphics now rejects UNC, device-namespace and reserved DOS paths on Windows** (github, 2026-09-09) [link](https://github.com/ghostty-org/ghostty/commit/cf4de795be50ec5bfe6675803a3371d4055f2beb)

- **Windows terminal pages get their memory back through DiscardVirtualMemory** (github, 2026-09-09) [link](https://github.com/ghostty-org/ghostty/commit/95cfbbb055c659f57da3650cfb733dbb5072f6a5)
  Unused memory behind the terminal's page pool and its compressed pages could already be reclaimed on Linux and macOS; Windows now does it too, via `DiscardVirtualMemory`. His reasoning for that call over the obvious alternative is the substance of the commit: it releases the physical pages behind a committed range but leaves the range committed, so a later access finds a zero page or the old contents rather than faulting, nothing has to be committed again before reuse, recommit stays a no-op, and — the deciding property — restoring a compressed page stays infallible. `VirtualFree(MEM_DECOMMIT)` followed by `VirtualAlloc(MEM_COMMIT)` would also release the commit charge, but Windows has no overcommit, so that commit can be refused on restore and the restore path has no OOM handling.

  70 lines across `os/windows.zig`, `terminal/PageList.zig` and `terminal/mem.zig`. Worth reading next to the TinyIo commit of the same day: both trade a little Windows-specific code for memory that scales with the number of terminals held open — the axis that matters to an embedder hosting many.
