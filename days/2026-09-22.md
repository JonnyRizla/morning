- **A missing default route was killing the Wi-Fi QR helper before its fallback could run** (github, 2026-09-21) [link](https://github.com/basecamp/omarchy/commit/5c2be2e6532a509a0db8ccb6a874f99b5b26c6ed)
  `bin/omarchy-network-qr` runs under `set -euo pipefail` and had the line `route_device=$(ip route get 1.1.1.1 2>/dev/null | awk …)`. A plain assignment takes the exit status of its command substitution, so on a machine with no default route the script died on that line — before reaching the connected-Wi-Fi fallback written directly underneath it, which would have found the interface anyway. The fix is three lines: `if ! route_device=$(…); then route_device=""; fi`.

  The test change is the better half. The stubbed `ip` in `test/shell.d/network-qr-test.sh` now reads a `QR_ROUTE_EXIT` variable and exits with it, and a new case — "network QR helper detects Wi-Fi when route lookup fails" — runs the whole helper with the route lookup forced to exit 2 and still expects a valid `WIFI:T:WPA;S:Cafe No Route;…` payload. The bug was invisible because every previous test had a route to find.
